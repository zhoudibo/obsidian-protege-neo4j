# 增量同步、备份与恢复演练

## 增量同步：核心是"谁拥有这个节点"

图谱和文件库最大的差别：**文件有明确归属，图节点没有**。

一个标签节点 `tag:客服` 可能被 5 篇笔记引用。你删掉其中一篇，不能顺手把标签也删了。

| 节点类型 | 归属 | 跟踪方式 | 删除策略 |
|---|---|---|---|
| 文件节点 | vault | 内容哈希 | vault 中消失 → 可删 |
| 目录节点 | vault | 目录存在性 | 目录消失 → 可删 |
| 标签节点 `tag:*` | **无归属** | 无 | **仅回收无入边的孤儿标签** |
| 源系统节点 `source:*` | 流水线 | 无 | **永不自动删** |

## 铁律：不能用"这次没扫描到"当删除依据

早期实现的做法是：把本轮扫到的文件 ID 与图里节点对比，图里多出来的就删。

**这个做法差点把未变更但仍被引用的标签一起清掉。**

正确做法：

```
文件/目录 → 对照 vault 的现存 ID（哈希基线），消失才删
标签      → 只回收无入边的孤儿（入边来自 TAGGED_WITH）
源系统    → 永不自动删
```

## 停手线

| 触发条件 | 动作 |
|---|---|
| 预计删除数超阈值（如 > 30%） | 停止删除，报警，人工确认 |
| 扫描量比上次骤降（如 < 50%） | 停止删除，查 vault 路径/挂载/过滤规则 |
| 出现歧义 wikilink | 跳过该链接并告警，不猜 |

停手线是**默认行为**，不是可选增强。任何绕过停手线的脚本都要在报告里注明。

## 四步增量验收（必做）

```text
① --dry-run：先看预计写入、预计删除；删除数异常就停。
② 新增 vault/经营笔记/临时卡.md，内含 [[商品资料]]，同步后查临时节点和 LINKS_TO。
③ 移走临时卡，再同步；确认临时节点被清理、商品资料仍在。
④ 对同一状态再跑一次；总数不应继续涨，重复边不应出现。
```

每一步记录**前后计数**。没有前后计数的验收等于没验收。

## 节拍

```
17:30  原文件同步完成
17:35  图谱增量同步
```

错开 5 分钟是为了确保图谱读到的文件已经是最终版本。钩子记住上次运行时间，日常只解析变更文件。

## 备份：两份，各有明确覆盖范围

| 备份 | 覆盖 | 不覆盖 |
|---|---|---|
| Git bundle | **已被 Git 跟踪**的文本 + 提交历史 | **未跟踪附件** |
| Neo4j JSON 逻辑导出 | 节点、关系、标签 | 全文内容（只存指针） |
| 同机 `.backup` | 数据库文件 | **不抵御整盘损坏** |

**Git bundle 不含未跟踪附件** —— 这是最容易被忽略的缺口。要覆盖全部内容，必须把附件也纳入 Git 跟踪（或用独立的对象存储备份）。

**同机备份不抵御整机损坏** —— 需要异盘或加密异地副本。

### Community 版的限制

`neo4j-admin database dump` 在 Community 版要求**数据库离线**。不能拿在线 dump 当本方案已跑通——参数和可用性随版本和企业版授权变化，**以本机 `--help` 为准**。

### 逻辑导出的适配

导出文件是 JSON，节点结构因版本而异。校验脚本要兼容常见字段命名：

```
id / :ID / nodeId
start / :START_ID / startId
end / :END_ID / endId
labels / :LABEL
```

## 两级验证（必须分开写结论）

### A 级：导出完整性

```bash
python3 scripts/graph_verify.py --export ./neo4j.export.json --bundle ./vault.git.bundle
```

- 节点 ID 非空、唯一
- 每条关系两端都能在节点表找到
- 计数与在线库一致
- `git bundle verify` 通过

**能得出的结论**：备份文件结构可信。
**不能得出的结论**：能从别的机器恢复。

### B 级：隔离恢复（灾难恢复演练）

真正的恢复演练必须：

1. 演练库与生产库**端口、数据目录、凭据完全隔离**
2. 在演练库导入备份，记录**导入退出码**
3. 跑固定查询：节点数、关系数、3 条业务查询
4. 抽查若干原始卡片，核对链接
5. 记录：备份日期、源/目标版本、开始与结束时间、节点/关系差异、失败处理人

```cypher
MATCH (n:KBNode) RETURN count(n) AS nodes;
MATCH ()-[r]->() RETURN count(r) AS relationships;
MATCH (a:IndexCard)-[:LINKS_TO]->(b) RETURN a.title, b.title LIMIT 10;
```

**任一步不符 → 结论写"恢复未通过"，并保留旧备份，不用新快照覆盖唯一可用副本。**

演练库绝不能直接覆盖在线库。
