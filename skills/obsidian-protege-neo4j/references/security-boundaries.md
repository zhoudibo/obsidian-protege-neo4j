# 安全边界与脱敏红线

> 图谱把散落的私密信息集中到一处。**集中本身提高了泄露半径**，所以边界的严谨程度必须高于普通笔记工具。

## 一条不可协商的架构边界

```
Obsidian 原文件 = 事实源（source of truth）
Neo4j           = 派生副本（derived projection）
```

**任何导入脚本都不得改写源文件。** 这条保证了：图谱可以整个删掉重建，笔记永远安全。

推论：Neo4j 是"可丢弃"的。这正是敢做图谱的前提——如果图谱是唯一副本，任何一次同步 bug 都是灾难。

## 数据分层：什么该进图，什么不该

| 数据 | 进图？ | 处理方式 |
|---|---|---|
| 业务实体主数据 | ✅ | ERP 主数据是权威源 |
| 交易数据 | ✅ | 形成事实，权限决定是否投影 |
| 文档元数据 | ✅ | 只同步已审核元数据 |
| 文档版本 / 知识切片 | ✅ | 需 `securityLevel` + 有效期 |
| 原始合同、图纸、照片 | ❌ | 留在对象存储，图库只存**来源指针** |
| 身份证号 | ❌ | 绝不写入图数据库 |
| 银行卡号 | ❌ | 绝不写入图数据库 |
| 完整联系方式 | ❌ | 默认不投影 |
| 银行账号、保证金 | ❌ | 绝不写入图数据库 |
| 生产密钥 / 密码 | ❌ | 绝不写入图数据库 |
| 未脱敏原文 | ❌ | 绝不写入图数据库 |
| 金额 | ⚠️ | 按权限决定是否投影 |

## 公开/共享图谱的特殊要求

**先用副本试跑。** 明确列出排除规则：

```bash
python3 scripts/kb_etl.py --vault ./vault --out ./out \
  --exclude "Private/*" \
  --exclude "客户资料/*" \
  --exclude "家庭/*"
```

排除规则要**显式写出来并可审计**，不要靠"我记得那个目录不该导"。

**不要靠"图上不点开"来保护私密内容。** 图数据库的权限边界是技术问题，不是纪律问题。

## 权限过滤的顺序（关键）

```
用户提问
   ↓
① 权限过滤（用户有权访问的内容集合）    ← 必须最先
   ↓
② 检索召回
   ↓
③ 生成回答
```

**权限过滤必须先于召回和生成。** 反过来做——先召回再过滤——意味着模型可能已经"看见"了无权访问的内容，即使最终回答里没提，泄露已经发生。

只有**已发布、当前有效、且用户有权访问**的文档、版本和切片，才进入默认图谱检索与 AI 回答。

## 凭据处理

```yaml
# 凭据文件权限
-rw-------  1 user  staff  512  credentials.json   # 600
```

- 凭据用**文件**（`credentials_file`），不用配置项里的明文 `password`
- 审计脚本**只报告"命中位置与条数"，绝不把密码原文写进报告或终端**
- 秘密留在受保护凭据文件，报告里只出现位置和条数

```yaml
# ✅ 报告该这样写
[凭据扫描] 命中 2 处，明文未记录
    位置：./config/legacy.yml:14
    位置：./notes/2026-10-27.md:88

# ❌ 报告不该这样写
[凭据扫描] 密码是 SuperSecret123
```

### 体检脚本自己会腐烂

一个旧版月度图健康脚本仍在读已迁走的 `password` 配置项，当前配置已改为 `credentials_file`，**本轮实际执行直接报错**。

这不是文档问题，是**代码问题**。安全治理必须包含"治理脚本本身是否随凭据迁移更新"。

修完还要重跑，不能只改代码就宣布通过。

## 审计报告要分层

| 层级 | 动作 | 能得出什么 |
|---|---|---|
| A 级：结构完整性 | 读 JSON 核 ID / 端点 / 计数 | 文件结构可信 |
| B 级：隔离恢复 | 空库导入 + 固定查询 | 灾难恢复成功 |

只做了 A 级，结论**不能写"恢复成功"**。同理，只做了"文件存在"检查，不能写"备份体系已就绪"。

## 月度安全体检清单

```
□ Git 工作区状态（未提交改动数量，> 0 就是 WARN 不是 PASS）
□ 凭据文件权限（是否 600）
□ 私密内容是否被 Git 跟踪
□ 备份新鲜度（最近一次备份时间）
□ bundle 可打开性
□ 逻辑导出结构（节点 ID / 关系端点 / 计数）
□ Neo4j 连通性
□ 待审队列是否有积压
□ 图健康脚本自身能否跑通（不报错）
```

**"全绿"是结论，不是默认状态。** 上一版报告有 35 个未提交改动的 WARN——就该写 35 个 WARN。

## 演练环境的隔离

做恢复演练时：

- 演练库与生产库**端口、数据目录、凭据完全隔离**
- 用**新建、空的、可丢弃**的数据库
- 绝不直接覆盖在线库
- Docker 部署时用 `secrets` 挂载凭据，不写在环境变量明文里

```yaml
services:
  neo4j:
    image: neo4j:<version>
    ports:
      - "127.0.0.1:7474:7474"    # 只绑回环，不暴露
    secrets:
      - neo4j_auth
    environment:
      NEO4J_AUTH_FILE: /run/secrets/neo4j_auth
```

## 报告表述纪律

区分**已验证**和**未验证**：

| 表述 | 含义 |
|---|---|
| "本轮核验：OWL 可解析，33,076 三元组、13 个类" | 已验证，有命令输出支撑 |
| "已实现隔离库恢复" | 必须有导入退出码 + 计数 + 查询结果 |
| "增量同步已验证" | 必须有四步验收的前后计数 |
| "备份体系已就绪" | 必须有 B 级恢复证据 |

**不要把设计意图写成已验证能力。** 这条铁律能挡掉绝大多数复盘里的注水。

## 复刻提示词模板（给 AI 编程助手 / Codex）

```text
请只读取我给的 demo_vault 三张虚构 Markdown，不访问我的真实 Obsidian 库，
也不要连接或修改现有 Neo4j。

目标：做一个可回放的最小知识图谱演练。
1. 先列出你读到的文件相对路径、frontmatter 标签和 [[wikilink]]，标明缺失或歧义。
2. 给出 4 类节点（Directory、IndexCard、Document、Tag）和 3 类关系
   （CONTAINS、LINKS_TO、TAGGED_WITH）的本体草图，并说明 Protégé 中的类、
   对象属性、方向。
3. 生成标准库 Python 脚本输出 nodes.csv 与 relationships.csv；所有节点用相对
   路径或 tag: 前缀做稳定 ID。离线导入 CSV 同时保留 :ID 和普通 id 属性，
   所有节点加 KBNode 标签。
4. 写四个验收：节点 ID 唯一、关系端点均存在、同一数据二次导入不重复、
   增量删一张临时卡不误删仍被引用的节点。
5. 先输出 dry-run 预估；若预计删除非零或扫描量突然下降，不执行删除，
   写明原因与人工接手步骤。
6. 最后给每日同步、每日备份、月度校验、隔离库真正恢复四张独立检查卡。
   任何未实际运行的步骤标"待验证"，不要写"已上线"或"恢复成功"。

请先给计划与文件清单，等我审阅后再生成脚本；
绝不读取凭据明文或把路径/内容发到外网。
```
